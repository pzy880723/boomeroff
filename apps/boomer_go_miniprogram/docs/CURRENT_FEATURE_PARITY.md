## Priorities

1. Native retake/expired-attempt recovery and no-shop personal month are locally verified; real employee/device acceptance remains open.
2. Separate daily working-shop truth from server-authorized content-shop context. A missing shift must not be treated as absence of all daily content rights; never guess the first/only store.
3. Add authorized schedule write flows with atomic server operations, explicit independent capabilities, CAS and original-request receipts. Keep seven-day scheduling allowed; do not restore the old five-day cap.
4. Migrate remaining activity/voucher operations, then marketing asset/account lifecycle. Do not restore rejected separate AI-image/copy/advanced-video menus.

## Release Gates

Tourist preview, synthetic screenshots, unit tests and anonymous 401 checks do not prove production employee flows. Dedicated AppID, required WeChat domain/privacy configuration and genuine employee/device acceptance remain mandatory. No public release or full functional parity is claimed.

## Store-Context Finding

Fixed backend `current_shop_context_v1` returns authorized shops but leaves `effective_shop` empty on rest/unscheduled days. Bootstrap separately contains a server-read `staff_profile.shop_id`, which is not proven immutable authority. Existing Web marketing accepts only an explicit bound shop that is still visible; it never guesses from list size. New native KB gates require the daily effective shop, so a client-only home fallback would still fail and would not constitute an authorization fix. This is an open coordinated backend/client item, not a completed feature.

Further source audit found that staff_profiles has an own-user INSERT/UPDATE branch without a shop_id constraint; a server-read field is not therefore immutable authority. No canonical home was found in the current ERP mirror contract. CONTENT_CONTEXT_AUDIT.md records this unresolved prerequisite and the unapproved R27 plan. No home fallback, policy change or rest-day authorization expansion has been deployed.
