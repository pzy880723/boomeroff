# BOOMER GO 微信小程序初版验收说明

2026-10-16。当前是可在官方开发者工具运行的原生初版，不是已发布的小程序。

## 五个入口

| 入口 | 初版内容 |
| --- | --- |
| 工作台 | 当前员工与工作门店、今日班次、待办、只读门店业绩、龙虎榜入口、运营工具。 |
| 学习 | 知识搜索、知识详情、SOP／问答维护及独立授权分类管理、知识测试、测验记录、个人知识与收藏。 |
| 识物 | 原生相机、逐拍直接进入图片栏、最多五张、多角度识别、完整商品故事与卖点、显式保存。 |
| 消息 | 通知、同事会话、联系人、聊天与原文件附件；未读和发送结果由后台确认。 |
| 我的 | 员工资料、自己的门店与排班、成长签到、25级成长反馈、任务、知识测验记录、活动、优惠券、营销工具和退出。 |

所有入口和二级页面使用 WXML/WXSS/原生微信组件；没有 web-view、网页跳转或客户小程序跳转。原有 iOS App 和客户 BOOMER OFF 小程序没有被替换。

## 业务规则

- 员工业绩只展示，不计入培训考试分数，不参与处罚或绩效考核。
- 龙虎榜必须有真实订单的员工销售归属。目前缺此归属，因此明确空榜与原因，不编造排名。门店付款毛额与退款净额不能混称。
- 店员只使用后台授权的工作门店；仅总部已有授权允许切店，不新增跨店权限。
- 测试在服务端出题、评分和保存结果。客户端不能自行提交“已经通过”的成绩。
- 识物使用原生拍照路径，不逐张打开相册确认页；真机摄像头、连拍和权限体验还需实测。
- 营销保留统一智能视频流程、参考图、成片、封面和固定发布文案；下载使用原生相册接口，成功以系统回执为准，不能绕过相册授权。

## 已验证与待验证

当前手工文案迁移源码完整自动化测试 1846/1846 通过；27 个原生路由静态检查通过，官方28 WXML／29 WXSS编译通过。五个Tab保持不变；活动编辑器仍只开放开发预览，不算已验收的生产管理入口。具体源码提交和归档证据见VERIFICATION.md。

实际开发者工具已查看五Tab、OTP／密码界面、单篇和连续学习、重考、知识库维护、本人月历与七日排班管理。中文草稿输入、分类数字排序、答题回顾、跳过与退出等有合成操作截图；这些不是员工身份、写库或摄像头硬件验收。

后续已增加本店最近50条发布记录及原生只读任务详情、25级成长反馈和规则、识物故事与收藏核对流程。原生关闭、展开／收起、滚动等已实际操作；未知写入结果与异步竞态由模拟测试验证。工作台和营业页仅在前台定时读取，缺失金额和个人销售归属明确不可用，不编造实时数据或员工排名。当前包及各轮具体证据见VERIFICATION.md。

素材库新增原生手动文案入口，支持本人本店的创建、候选编辑、单独确认删除和原编号核对。没有恢复独立AI文案入口，不调用付费模型或发起发布。此项仍需真实员工写库验收；不能将页面预览或输出文字相等条件称为完整版本锁、持久回执或恰好执行一次。

活动凭证 Stage2 的原图选择、进度、未知结果恢复和关联参数已对齐固定 Round16/17 源码；Lovable 回报迁移／Edge 部署，独立源码复核确认两条 P2 已闭合。当前对象不匹配时保留原路径但不签名或允许新关联。旧测验重放persisted缺失已由Round18首次事实修复并经固定源码复核，Lovable报已部署和合成SQL回滚通过。尚未验证真实员工上传或学习保存，其他既有后台接入也不替代员工端到端验收。

还需专用 BOOMER GO 员工小程序 AppID、主体／类目、合法域名、隐私配置和真实员工手机验收，才能提交体验版／审核。当前 touristappid 不能作为员工正式分发入口，也不会复用客户小程序 AppID。

“功能全部迁移”尚未完成。七日排班单格管理已经实现客户端，但原子换班／清周、班次与禁排日设置等仍缺；活动创建编辑只在开发预览，后台R36停在人工费用检查点。活动审核／发券／短信、券模板管理、完整发布账号与素材管理、识物管理／精修及其他角色专属功能仍有缺口。当前状态统一见CURRENT_FEATURE_PARITY.md，FEATURE_PARITY.md保留历史审计，不能用其早期状态覆盖现在的实现。

没有绕过Lovable的费用确认，没有增加跨店权限。账号邀请的旧Web客户端是分开修改邀请和插入角色，不能直接作为原生可靠授权协议迁移。真实员工、专用AppID、隐私／合法域名和微信发布必须另行验证。当前没有体验版二维码，也未声称已上线。
