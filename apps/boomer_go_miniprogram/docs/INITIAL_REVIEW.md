# BOOMER GO 微信小程序初版验收说明

2026-10-16。当前是可在官方开发者工具运行的原生初版，不是已发布的小程序。

## 五个入口

| 入口 | 初版内容 |
| --- | --- |
| 工作台 | 当前员工与工作门店、今日班次、待办、只读门店业绩、龙虎榜入口、运营工具。 |
| 学习 | 知识搜索、知识详情、SOP、问答、知识测试、测验记录、个人知识与收藏。 |
| 识物 | 原生相机、逐拍直接进入图片栏、最多五张、多角度识别、完整商品故事与卖点、显式保存。 |
| 消息 | 通知、同事会话、联系人、聊天与原文件附件；未读和发送结果由后台确认。 |
| 我的 | 员工资料、自己的门店与排班、成长签到、任务、考核记录、活动、优惠券、营销工具和退出。 |

所有入口和二级页面使用 WXML/WXSS/原生微信组件；没有 web-view、网页跳转或客户小程序跳转。原有 iOS App 和客户 BOOMER OFF 小程序没有被替换。

## 业务规则

- 员工业绩只展示，不计入培训考试分数，不参与处罚或绩效考核。
- 龙虎榜必须有真实订单的员工销售归属。目前缺此归属，因此明确空榜与原因，不编造排名。门店付款毛额与退款净额不能混称。
- 店员只使用后台授权的工作门店；仅总部已有授权允许切店，不新增跨店权限。
- 测试在服务端出题、评分和保存结果。客户端不能自行提交“已经通过”的成绩。
- 识物使用原生拍照路径，不逐张打开相册确认页；真机摄像头、连拍和权限体验还需实测。
- 营销保留统一智能视频流程、参考图、成片、封面和固定发布文案；下载使用原生相册接口，成功以系统回执为准，不能绕过相册授权。

## 已验证与待验证

本轮完整自动化测试 728/728 通过；22 个原生路由静态检查和官方 23 WXML／24 WXSS 编译通过。五 Tab、OTP／密码登录、单篇与连续学习的阅读／答题／回顾／下一条／跳过／退出，以及本店SOP/QA列表／Markdown阅读／编辑控件／共享只读等已在真实开发者工具查看；示例数据有明确标签，不是真员工登录、知识保存或成绩入库证据。编辑输入值的实际GUI验收仍待补。

活动凭证 Stage2 的原图选择、进度、未知结果恢复和关联参数已对齐固定 Round16/17 源码；Lovable 回报迁移／Edge 部署，独立源码复核确认两条 P2 已闭合。当前对象不匹配时保留原路径但不签名或允许新关联。旧测验重放persisted缺失已由Round18首次事实修复并经固定源码复核，Lovable报已部署和合成SQL回滚通过。尚未验证真实员工上传或学习保存，其他既有后台接入也不替代员工端到端验收。

还需专用 BOOMER GO 员工小程序 AppID、主体／类目、合法域名、隐私配置和真实员工手机验收，才能提交体验版／审核。当前 touristappid 不能作为员工正式分发入口，也不会复用客户小程序 AppID。

“功能全部迁移”尚未完成：角色专属管理写入、活动审核／创建、券发放、排班管理、完整发布账号管理等缺口逐项保留在 FEATURE_PARITY.md。不能把一个列表或可点击菜单算作完整业务闭环。
